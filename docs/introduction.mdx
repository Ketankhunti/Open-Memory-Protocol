**Open Memory Protocol (OMP)** is an open standard that lets AI applications read, write, and search persistent user memory through **one API**, against **any backend** — Mem0, Supermemory, Zep, Notion, Postgres, or a self-hosted vault — without changing application code.

OMP is to AI memory what **S3** is to object storage, **OAuth** is to identity, and **MCP** is to LLM tools.

## Why OMP

Today every memory provider has a different SDK, schema, auth model, and concept of users and scopes. App developers must:

- Pick **one** provider and lock users in, **or**
- Build N integrations (most don't), **or**
- Skip memory entirely.

End users cannot bring memory across apps, switch providers, or audit what each app reads.

OMP fixes this with a small, unambiguous protocol covering the 80% memory use case, plus reference SDKs and adapters that bridge existing providers today and let providers implement OMP natively tomorrow.

## How it relates to MCP and A2A

| Standard | What it standardizes |
|---|---|
| **MCP** (Model Context Protocol) | How agents talk to **tools** |
| **A2A** (Agent2Agent) | How agents talk to **other agents** |
| **OMP** (Open Memory Protocol) | How agents talk to **memory** |

The three are complementary. An agent can use MCP for tools, A2A for delegation, and OMP for persistent memory — across the same user, across vendors.
