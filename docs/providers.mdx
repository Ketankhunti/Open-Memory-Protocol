OMP is provider-neutral. Any backend that implements the spec — natively or via an adapter — is a provider.

## Reference adapters (shipped in `openmem`)

| Provider | Adapter id | Mode | Status | `OMP_PROVIDER` |
|---|---|---|---|---|
| **Postgres + pgvector** | `postgres` | Native (reference) | Stable | `postgres` |
| **Native OMP endpoints** | `passthrough` | Passthrough | Stable | `passthrough` |
| **Mem0** | `mem0` | Translation | Stable | `mem0` |
| **Supermemory** | `supermemory` | Translation | Stable | `supermemory` |
| **Letta** | `letta` | Translation | Stable | `letta` |

`postgres` is the canonical native reference implementation. `passthrough` is a thin HTTP forwarder used to talk to any server (yours or someone else's) that already speaks OMP. The remaining three translate OMP verbs into each provider's native API.

## Configuring a provider

Each adapter reads its credentials from environment variables:

<CodeGroup>
```bash Postgres
export OMP_PROVIDER=postgres
export POSTGRES_URL=postgresql://user:pass@host:5432/dbname
# Requires the `vector` extension (pgvector).
```

```bash Mem0
export OMP_PROVIDER=mem0
export MEM0_API_KEY=...
```

```bash Supermemory
export OMP_PROVIDER=supermemory
export SUPERMEMORY_API_KEY=...
# Optional: SUPERMEMORY_BASE_URL to override https://api.supermemory.ai/v3
```

```bash Letta
export OMP_PROVIDER=letta
export LETTA_API_KEY=...
```

```bash Passthrough (any OMP-speaking endpoint)
export OMP_PROVIDER=passthrough
export OMP_BASE_URL=https://your-omp-server.example.com
```
</CodeGroup>

## Becoming OMP-native

Providers can implement OMP **natively** by exposing the [OMP 0.1 OpenAPI](/specification/0.1/openapi) at their own URL. The SDK auto-detects native support via `/capabilities` and uses **passthrough mode** (thin HTTP forwarding) — no translation overhead.

Native implementers earn the **OMP Native** badge once they pass the conformance suite (planned).

If you maintain a memory product and want to go native, open an issue or reach out via the GitHub repo.
